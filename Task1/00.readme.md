# Task1 / Проектируем домены

# Контекст

- GoFuture переходит от монолитного приложения на Django к микросервисам. Цель перехода — обеспечить поддержку 500 тысяч одновременных поездок, работу в нескольких регионах, доступность критически важных сервисов на уровне 99,95% и двухнедельный цикл выпуска продуктовых изменений.
- В первый год миграция будет строиться на паттерне Strangler Fig: функциональность монолита постепенно замещается новыми сервисами.
- Мобильные приложения, корпоративный портал и внешние клиенты сохраняют действующие REST-контракты, а API Gateway/BFF поэтапно перенаправляет доменные маршруты на микросервисы. 
- До переноса всех оставшихся сценариев монолит продолжает работать в качестве Legacy-контейнера.

# Карта доменных сервисов

| Сервис | Команда-владелец | Границы ответственности | Основные данные |
| --- | --- | --- | --- |
| Booking Service | Booking | Жизненный цикл заказа: создание, назначение, статусы поездки, отмены, оркестрация доменных вызовов | `bookings`, `trips`, `trip_status_history`, `cancellations` |
| Driver Service | Driver | Профили водителей, документы, смены, доступность, состояние водителя | `drivers`, `vehicles`, `driver_documents`, `driver_sessions`, `driver_availability` |
| Pricing Service | Pricing | Тарифы, динамическое ценообразование, правила надбавок, расчёт предварительной и финальной цены | `tariffs`, `pricing_rules`, `surge_zones`, `price_quotes` |
| Payments Service | Payments | Оплаты пассажиров, возвраты, корпоративные счета, выплаты водителям, интеграции с банками и платёжными шлюзами | `payments`, `refunds`, `invoices`, `payouts`, `ledger_entries` |
| Notification Service | Notification | Push, email/SMS при необходимости, шаблоны, предпочтения, токены устройств | `notification_templates`, `device_tokens`, `notification_preferences`, `delivery_attempts` |
| Geography Service | Geography | Геокодинг, маршруты, зоны, ETA, поиск подходящих водителей, интеграции с картами | `geo_zones`, `routes`, `places`, `driver_geo_index` |
| Analytics Service | Analytics | Сбор доменных событий, витрины для BI, real-time аналитика, экспорт в ClickHouse | `analytics_events`, `aggregates`, `bi_marts` |
| Fraud Service | Fraud | Антифрод-правила, скоринг поездок и платежей, списки риска, решения по блокировкам | `fraud_rules`, `risk_profiles`, `fraud_decisions`, `blacklists` |

# Обратная совмевстимость

- Все внешние команды имеют idempotency key, correlation id и версионированные DTO.
- Для данных используется expand-contract: сначала добавляются новые поля и таблицы, затем включается синхронизация, после проверки чтение переводится на новый сервис, и только потом удаляются старые зависимости.
- Для синхронизации применяется transactional outbox/CDC: это снижает риск потери событий при разделении БД.
- Переключение выполняется feature flags и canary по региону, городу, партнёру или доле трафика.
- API Gateway/BFF сохраняет старые URL, версии REST API и форматы ответов для мобильных приложений и корпоративного портала.
- Для уже выделенных доменов gateway маршрутизирует трафик в сервисы, для остальных маршрутов оставляет вызов монолита.
- В монолите остаётся anti-corruption layer: старый код обращается к новым сервисам через адаптеры и не читает напрямую их новые базы.
