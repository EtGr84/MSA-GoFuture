# Task2 / Проектируем Event-Driven архитектуру

# Контекст

Для 500 тысяч конкурентных поездок, динамического ценообразования и realtime-аналитики GoFuture нужна событийная платформа. Синхронные REST-вызовы остаются для пользовательских команд и коротких запросов, но доменные изменения публикуются как события и обрабатываются независимыми потребителями.

# Ключевые решения

- Основной event backbone: Apache Kafka / Yandex Managed Service for Kafka в каждом регионе развёртывания.
- Партиционирование: `region_id + aggregate_id`, чтобы локализовать нагрузку и сохранять порядок событий внутри бизнес-агрегата.
- Контракты: Protobuf/Avro + Schema Registry, совместимость минимум backward-compatible.
- Надёжная публикация: transactional outbox в доменных БД + Debezium/Kafka Connect.
- Обработка realtime-потоков: Flink или Kafka Streams для pricing signals, driver allocation signals, fraud features и аналитических агрегатов.
- Saga: оркестрируемая Saga в Booking Service для создания и подтверждения поездки.
- Мониторинг: Prometheus, Grafana, Alertmanager, Kafka/JMX Exporter, Burrow или Consumer Lag Exporter, Loki, Tempo/Jaeger, OpenTelemetry Collector.
